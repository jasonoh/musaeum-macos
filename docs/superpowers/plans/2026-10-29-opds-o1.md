# OPDS Catalog — Slice O1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An OPDS 1.2 server in the running app, reachable over the tailnet, so the Boox Palma can browse, search and download the library without BooxDrop.

**Architecture:** A pure feed builder (`services/opds/feed.ts`) and a pure Basic-auth check (`services/opds/basic-auth.ts`) carry the protocol logic. `api/opds.ts` is a thin `node:http` server plus its own start/stop/status lifecycle, a deliberate sibling of `api/rest.ts` (which is 66 KB, carries a different contract, and whose tests forbid binding the real tailnet). It reuses `services/api/bind.ts`, `tokensMatch`, `book-bytes.ts` and the existing paged DB queries. `services/settings.ts` gains four `opds_*` keys and a Settings row that mirrors *Phone access*.

**Tech Stack:** Electron main (Node `node:http`), better-sqlite3, vitest, React + Tailwind (one Settings section).

**Spec:** `docs/superpowers/specs/2026-09-19-opds-catalog-design.md` — read the *Amendment 1 (2026-10-29, the trigger and Tailscale)* first; it supersedes D4, the Security bind rules, AC2.10 and AC2.14. Rules to read before editing: `docs/invariants/settings-and-editing.md` (§ *The phone API's four keys*), `docs/invariants/reader.md` (containment), `docs/invariants/files-and-deletion.md` (extension resolution), `docs/invariants/library-views.md` (invariants 3, 4).

## Global Constraints

- OPDS **1.2 Atom/XML**, hand-rolled; **no new dependency** (D7). `node:http` + one `escapeXml`.
- Navigation feed media type exactly `application/atom+xml;profile=opds-catalog;kind=navigation`; acquisition exactly `application/atom+xml;profile=opds-catalog;kind=acquisition`.
- Every acquisition link has a `type`; rel is `http://opds-spec.org/acquisition/open-access`. Formats iterate `orderedFormats()` — **never `formats[0]`** (invariant 3).
- Format media types: epub `application/epub+zip`, pdf `application/pdf`, mobi and azw3 both `application/x-mobipocket-ebook`.
- Entries are **Complete, inline**; `atom:id` = `urn:uuid:<book.id>`; `atom:updated` falls back `lastModified` → `dateAdded` → `1970-01-01T00:00:00Z`; summary `type="text"`, truncated.
- Auth: HTTP **Basic**, username `musaeum`, password = the token; 401 with `WWW-Authenticate: Basic realm="Musaeum"`; compare with `tokensMatch` (constant time); log the client address only.
- Keys: `opds_enabled`, `opds_port` (default **8789**, range 1024–65535), `opds_bind` (blank = tailnet; saved value must satisfy `isAllowedBindAddress`), `opds_token` (32 random bytes hex, generated on enable if absent, never sent by the UI).
- Disabled (the default) means nothing listens. A bind failure is recorded, never thrown (invariant 12). NAS offline: feeds serve from SQLite, downloads and covers' bytes answer **503**; unknown book/format/traversal is a uniform reason-free **404**.
- Download/cover bytes resolve only through `resolveBookFile` / `resolveCoverFile` (invariant 9). No `file://` anywhere.
- Business logic in `services/`; `api/opds.ts` stays thin (invariant 8). Sorting/paging reuse `db.getBooksPage` / `db.searchBooksPage` — **no second SQL path** (invariant 4).
- Whole-file downloads only; no Range, no ETag, no facets (spec *Out of scope*).
- Markdown prose is not hard-wrapped.

## Review Focus

Failure modes the spec implies that no acceptance criterion names; each has a test in the owning task.

1. **Credential with a colon or non-ASCII byte in the Basic header** — the password is split on the *first* colon only; a malformed base64 payload is a 401, never a 500 (Task 2).
2. **A `?q=` that is empty, only quotes, or very long** — an empty search must not throw or return an empty catalog the client caches; it returns the library page, as the app's own search does (Task 4).
3. **A page number past the end, `page=0`, `page=-1` or `page=abc`** — answer the clamped/first page or 400 deterministically, never an OFFSET of NaN (Tasks 1, 4).
4. **A book whose description contains characters illegal in XML 1.0** (control chars `\u0000`–`\u0008`, lone surrogates) — the feed must stay well-formed, because one bad book would otherwise break every page it appears on (Task 1).
5. **Client hangs up mid-download** — the stream closes and the next request still works; no unhandled `'error'` takes the process down (Task 4).
