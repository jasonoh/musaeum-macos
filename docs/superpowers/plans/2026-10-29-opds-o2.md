# OPDS Catalog — Slice O2 (browse tree) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace "one enormously long list" on the Boox Palma with a browse tree: Unread, Authors A–Z, Series A–Z and Titles A–Z, each narrowing to a short list before any book list.

**Architecture:** A pure initial-letter helper (`services/initials.ts`) is registered into SQLite as `musaeum_initial`, so the bucket a name falls in is derived once and used by both the grouping SQL and the filter. `db.ts` gains three read functions and one filter on its existing `getBooksPage`. A new `services/opds/browse.ts` owns the route table and assembles each browse feed; `feed.ts` gains a navigation-feed builder; `api/opds.ts` gains one dispatch line.

**Tech Stack:** Electron main (Node `node:http`), better-sqlite3, vitest. No renderer change, no new dependency.

**Spec:** `docs/superpowers/specs/2026-09-19-opds-catalog-design.md` — the *Routes (slice O2)* table, AC2.16–AC2.18, and *Amendment 2026-10-29*. This plan deviates from the O2 route table in four places (the **Calls** below); Task 5 records them as the spec's Amendment 2. Rules to read before editing: `docs/invariants/library-views.md` (invariants 3 and 4, the sort keys), `docs/invariants/settings-and-editing.md` → *Known limits (O1)*.

## Calls this plan makes (the spec is silent or says otherwise)

1. **Two levels, not one.** The spec's `/opds/authors/{letter}` is an acquisition feed of every book under a letter — about 270 books under "S" in a 7,000-book library, which is the same long-list problem one level down. Here a letter opens a **navigation feed of names with book counts**, and a name opens that author's books. Same for series. *Cost if wrong:* one extra tap; the spec's shape is a subset of this one.
2. **Titles A–Z is added** (`/opds/titles`, `/opds/titles/{slug}`). It is the only fix for "All" itself, which stays as the complete list that search runs against.
3. **Unread means the app's `unread` status only** (`readStatus: ['unread']`), not the spec table's `read_status != 'read'`. AC2.18 says it must equal `getFacets().readStatus`'s unread count, and that count excludes `reading`. AC2.18 is the binding instrument; *Cost if wrong:* books marked `reading` are absent from Unread — they are one tap away in All.
4. **A name is the exact stored string.** "Neil Gaiman & Terry Pratchett" is its own author entry, the sidebar facet's rule. Splitting co-authors is a later decision (`splitAuthors` exists). Books with no author or no series are not in those trees; they are in All, Titles and Search.

## Global Constraints

- Everything O1's plan lists still binds: OPDS 1.2 Atom/XML, no new dependency, exact navigation and acquisition media types, `orderedFormats()` never `formats[0]`, Basic auth before routing, uniform reason-free 404, `charset=utf-8` accepted.
- Navigation entries link with `rel="subsection"` and `type` = `OPDS_NAV_TYPE` when the target is a navigation feed, `OPDS_ACQ_TYPE` when it is an acquisition feed.
- Bucket slugs are `A`–`Z` and `other`. A letter slug in a path is accepted case-insensitively and normalized; anything else is 404.
- A bucket is `A`–`Z` (after stripping diacritics and leading non-alphanumerics) or `#` (digits, non-Latin scripts, nothing left). `#` is spelled `other` in URLs.
- **Every name appears under exactly one bucket**, and the letters feed lists only buckets that hold at least one book.
- Book pages reuse `db.getBooksPage` and `OPDS_PAGE_SIZE` (80). Name lists page at `OPDS_NAV_PAGE_SIZE = 200` (a navigation entry is about 450 bytes, so a page is about 90 KB).
- Sorting and paging come from the existing `orderClause`; **no second ORDER BY** (invariant 4). `src/types/` is not touched.
- Feeds serve from SQLite, so the NAS being offline changes nothing here.
- Markdown prose is not hard-wrapped.

## Review Focus

Each line has a test in the owning task.

1. **An author or series name with `/`, `%`, `?`, `#`, `&`, a quote, or non-ASCII** — the link round-trips to exactly that name's books (Tasks 3, 4).
2. **Names starting with an accented letter, a digit, a leading quote, or a non-Latin script** — exactly one bucket, reachable, never lost (Task 1).
3. **The same author string with different `author_sort` across books** — still one bucket, one entry (Task 2).
4. **Counts that disagree** — the letters feed's counts must sum to the books reachable beneath them, and the unread feed's total must equal the facet (Tasks 2, 4).
5. **A bad slug, a bad `page`, a page past the end, an unknown name** — 404, 400, 200-empty, 200-empty respectively; never a throw (Task 4).
