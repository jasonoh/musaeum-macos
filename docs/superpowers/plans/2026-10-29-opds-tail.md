# OPDS tail (counts in titles, Unread letters, O2 cleanup) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the O2 browse tree usable on the Boox Palma's KOReader (visible counts, a shorter Unread) and close the O2 review's minors and test gaps.

**Architecture:** All changes sit in `electron/main/services/opds/{browse,feed}.ts`, `services/db.ts` (one optional filter parameter) and `api/opds.ts` (one helper reuse). No new routes except `/opds/unread/{slug}`; `/opds/unread` changes from an acquisition feed to a navigation feed of letters, reusing the Titles bucket machinery with `readStatus: ['unread']`.

**Tech Stack:** TypeScript, better-sqlite3, vitest (run only via `npm test`).

**Spec:** `docs/superpowers/specs/2026-09-19-opds-catalog-design.md` (Amendments 1 and 2; this plan adds Amendment 3). Also read `docs/invariants/settings-and-editing.md` → *Known limits (O1)* and *(O2)*.

## Global Constraints

- Branch from `main` in a worktree. Do not merge or push; the owner decides after a `reviewer` pass.
- Invariants 4 (sort keys / one query path) and 8 (logic in services, thin handlers) apply: every list is read through `getBooksPage`, `listNamesByInitial`, `countBooksByInitial`; a book is counted under the letter it is listed under.
- Entry `id`s and URL paths do not change except for the new `/opds/unread/{slug}`. Only entry `title`s gain a count.
- Page sizes stay: `OPDS_PAGE_SIZE = 80` for book pages, `OPDS_NAV_PAGE_SIZE = 200` for name lists.
- Markdown prose is not hard-wrapped. `npm run typecheck && npm run lint && npm test` must be clean before the final commit; test-name format and fixtures follow `browse.test.ts` and `api/opds.test.ts`.
- Out of scope, deliberately: LAN bind, OPDS 2.0, co-author splitting, a login-time retry (proposal only, item 4 of the brief).

## Review Focus

- A name or letter with exactly one book reads `(1)`, not `(1 books)`; the suffix is a bare number.
- A name that already ends in parentheses or digits (`Foo (2)`) still reads unambiguously and its `by-author` path still resolves to the stored name (the suffix is in the title only, never the path or id).
- Unread letters: a letter whose books are all read does not appear; a book marked `reading` appears in no Unread letter (Amendment 2, call 3) and the letter counts sum to `getFacets().readStatus` unread.
- Unread letter paging: a bucket of more than 80 unread books pages with `next` links that stay under `/opds/unread/{slug}`.
- The empty library and an all-read library: `/opds/unread` answers 200 with zero entries, never a 404 or 500.
