# The voice reader

**Read before:** touching `sidecar/tts/`, `scripts/build-espeak.sh`, the speech model's download, `services/tts.ts`, or anything that speaks a book. Design: `docs/superpowers/specs/2026-10-15-voice-reader-design.md`; the engine's build record: `docs/superpowers/plans/2026-10-15-voice-reader-engine.md` (see its annex); the reader half's plan and build record: `docs/superpowers/plans/2026-10-15-voice-reader-ui.md` (see its annex).

## The rules, and what each one cost to learn

- **espeak-ng is the bundle we build, never the pip wheel.** The pip `espeakng-loader` is installed transitively by `kokoro-onnx` and never used (our code always passes both `lib_path` and `data_path`, so its library is never loaded); it compiles a build machine's data path into its binary (`/Users/runner/work/...`) and espeak calls `exit()` when it cannot read `phontab` there — measured on 0.1.51, 0.2.1 and 0.2.4, and no runtime path rescues it. `scripts/build-espeak.sh` builds 1.52.0 from a pinned tarball; the library takes its data directory at run time (`espeak_Initialize`'s `path`, the directory that *contains* `espeak-ng-data`), so the bundle is relocatable. `find_espeak()` checks for `phontab` itself, so a missing file is a sentence, not a dead process. Two builds produced byte-identical data and dylib.
- **The bundle ships `en_dict` only** (1.4 MB measured, 1,376,935 bytes, against 19.8 MB). It rides the existing `helpers/bin` entry in `electron-builder.yml`; `test/invariants.test.ts` pins that entry, because a narrower `from:` ships a build with no pronunciation and no code defect to find — which is exactly what happened once to the layout helper. The packaged-app gate passed 2026-10-15 (`Hegel` → `hˈɛdʒəl`).
- **GPL-3.** espeak-ng is linked dynamically through `ctypes` into a personal app that is not distributed. The day the app is distributed to anyone else, the combination is re-read against the licence before the first copy leaves the machine.
- **Three lanes.** `tts_synthesize` has a lane of its own (`main.TTS_POOL`, one thread): a sentence queued behind a Google Books call is a voice that stutters. `tts_model_status` and `tts_cancel_download` run on a two-thread control lane (`main.CONTROL_POOL`, `main.CONTROL_LANE`), because a status or cancel is quick and must never wait behind a bulk refresh or a long `reflow_pdf` (the owner's choice, 2026-10-15; the spec's first reading put them on the shared pool, which could stall them up to the 120 s request timeout). `tts_download_model` stays on the shared four-thread pool, and the cancel-before-start property keeps the abandoned fetch from running: a cancel is acknowledged at once even while the download is still queued, and when the download eventually gets a thread it sees the cancel and returns `{ status: "cancelled" }` without fetching; but its own reply still waits for a free shared-pool thread, and the 30-minute app-side timeout in `services/tts.ts` is its only bound. CPU contention with the model's own threads is not measured here. `main()` drains all three pools at stdin EOF (commit 93215b5), because a lazy import in a worker during interpreter shutdown otherwise fails with "can't register atexit after shutdown"; the app never closes the sidecar's stdin, so this only matters to pipe-driven harnesses.
- **The model is loaded on use and dropped after 300 s idle**, and the idle timer only *tries* the engine's lock, so it can never drop the model under a call in flight; the timer is re-armed in a `finally` whenever the model is resident. int8 is +167 MB resident and 316 MB after its first sentence; full precision is 570 MB, against a 500 MB target, and was judged no better by ear — both from the pre-build bake-off, not re-measured here.
- **`SpeechEngine.synthesize` phonemizes before it verifies or loads the model.** That is deliberate, so silence never loads the model; the consequence is that a missing model is refused only for text that has something to say.
- **The model files are pinned by size and sha256** (`sidecar/tts/models.py`), live under `userData/tts-models/`, and are never in the DMG. A good file is never re-fetched; a corrupt one is replaced; a killed download leaves a `.part` that the next run overwrites. `model_status` reports `ready` on size alone, so a same-size corrupt file surfaces from `verify` as a "damaged" error, which the UI must route to a re-download. Cancel is checked between download chunks, so a stalled connection delays it up to the 30 s read timeout.
- **A refusal is `{ "error" }` in the sidecar and a rejection in `services/tts.ts`.** Text with nothing to say is *silence* (empty `pcm`, zero `duration_ms`), never an error, so a footnote marker does not stop a book.
- **Text is normalised for the failures measured on the real bundled espeak and model.** espeak reads a decimal point as a sentence end (`3.5 million` → "three. five million") and `$2.1 billion` as "two dollars. one billion"; `normalize_text` rewrites decimals and dollar amounts. It also strips what would otherwise be voiced: every `*` (`***` is "asterisk asterisk asterisk"), bracketed citation numbers (`[12]`, `[1,2]`, `[3-5]`; `[sic]` untouched) and emoji and pictographs (`😀` is "grinning face"; the U+2600–27BF dingbats range, the variation selector and ZWJ included). Text whose phonemes contain no alphabetic character (`...`, `—`, `?`, `“”`, `( )`) is silence, because the model otherwise renders a 260–550 ms non-word noise. **Known over-strip:** the dingbat range also strips ✝ ♀ ♂ ☉ ☿ ☞ ♪ ♥, misses ⭐ ⌚ ‼️ ℹ️, and `2*3` becomes `23`. Dates (`3/4/2021`) and clock times (`5:30 p.m.`) are **known gaps**, passed through untouched and recorded rather than half-handled.
- **The lexicon stores what a person typed** ("HAY-gul"; the part in capitals carries the stress), never IPA, and the phonemes are derived at synthesis. Whole words, case-sensitive, possessives handled, hostile entries ignored. The respelling cache is keyed per phonemizer instance (a `WeakKeyDictionary`), **never by `id()`** — a plan-mandated `id()` key aliased freed objects and caused a flaky test (commit 03fd426). Separator-only respellings are skipped. The derivation was listened to on 2026-10-15 (`HAY-gul`, `ko-ZHEV`, `af_heart` and `bm_george`) and sounded right to the owner (spec AC24).
- **No word-level timings.** Neither pinned model has a duration output (`has_timings` is False), so highlighting is per sentence.
- **The lexicon file is slice 3** and is not described here until it exists. The reader half (slice 2: `src/lib/speech-queue.ts`, `speech-player.ts`, `speech-controller.ts`, `speech-state.ts`, `src/hooks/useSpeech.ts`, `ListenBar.tsx`) follows; its rules are the ones below.
- **foliate's `tts.next()` rebuilds its range map, so the cursor never advances until the old block's last sentence has started.** `TTS#ranges` is rebuilt by every `next()`/`from()`, and `setMark(name)` resolves a mark name against the *current* block's map (names restart at "0" in every block). Advance early and the sentences still sounding or queued highlight the wrong text, or nothing. So the player never calls `take()` for the next block until `started(lastUnit)` has fired (prefetch never crosses a block boundary, and the *player* enforces that, not the controller), a unit that is no longer in the current block draws nothing, and a rewind resets the gate. A naive controller that advances on the take after the last unit fails four of the controller's tests, which is how the gate is pinned.
- **A section is not advanced until the old section's last sentence has ended, not started.** The first live pass (2026-10-15) found the page jumping to the next section 89 ms after the old section's last sentence *began* and 6,908 ms before it ended, so that sentence was spoken with its highlight off screen (EPUB, AZW3 and reflowed PDF alike). The fix is `PlayerSource.ended(unit)`, called once for every unit the player announced through `started()` when it stops sounding (the buffer's end, a silent unit as it starts, or a cut by `skip`, `restartAt` or `stop`; a unit replayed by `skip(-1)` ends when the replay ends). A block-to-block step inside a section still happens at `started()`; only a *section* step waits, and it waits outside the controller's serial queue so a page turn is not held up behind it. `ended()`, a restart, `abort()` and `dispose()` all wake the wait, so `take()` always settles; an end reported after a rewind is stale and is ignored; at the end of the book there is no wait. Measured on 6 crossings (3 EPUB, 2 AZW3, 1 reflowed PDF): the page moves **20 to 51 ms after the end**, the section load takes **24 to 55 ms**, and the next sentence is audible **698 to 702 ms after the end** (the block pause) with the next buffer scheduled 161 to 260 ms after the end.
- **Manual navigation is detected by containment, with no flags.** A relocate restarts speech only when the sounding sentence's start lies outside the page (both ends inclusive); a relocate onto a different document while the cursor is already there is our own section change and is not a move; a relocate onto a document the cursor is not on (a table-of-contents jump) rebinds and restarts; while our own `nextSection()` is in flight relocates are ignored; and after a restart the page start becomes the sounding anchor, so a second relocate onto the same page is not a move. Flags ("we caused this relocate") were the alternative; containment cannot go stale.
- **A restart drops sentences that start before the page.** foliate's `tts.from(range)` picks the first mark that *starts* at or after the page start inside the first block that ends after it; when the page opens inside a block's *last* sentence no mark qualifies and `#speak` returns the **whole block from mark 0**, which is on the previous page, so the highlight scrolled the reader back. Measured on a paused engine: 7 of 58 pages with the bar open, 11 of 69 with the search panel also open; the live failure was 13 of 24 ArrowRight trials, 10 of them the same page (Darwin chapter 4, pages 6 to 7). Figure captions are only the common case, because they are long single blocks. `onPage(units, page)` reads each unit's range through `tts.setMark` (with `tts.highlight` swapped for a capturing probe, then restored; the engine keeps its ranges private and `setMark` is its one way to hand one out) and drops the units that start before the page; a block dropped whole continues through `nextBlock()`, and a unit whose range cannot be read is kept. After the fix: 10 of 10 on the stuck page and 23 of 23 mixed turns. `begin(from)` (Read from here) is deliberately not filtered; see the open items in the plan's annex. When a page holds no sentence start at all (one sentence spanning pages) a turn restarts at the next sentence, so the reader scrolls forward, never back.
- **`tts.from()` throws on an image-only page or one past the last text block** (`undefined is not iterable`; a cover is the common case). `blockFrom()` catches it and the controller steps the section directly instead of calling `next()`, whose cursor may still sit on an earlier block. The d.ts says so.
- **`take()` always settles, and `abort()` is part of the `PlayerSource` contract.** A held take is settled with `null` by `abort()`, `dispose()`, a restart or the 10 s section deadline; a rewind that arrives while a take is in flight is applied after the take settles and the take's result is dropped. A step that does not move while later sections remain (the paginator is locked mid page turn) is retried every 150 ms inside the one 10 s deadline; the end of the book is decided from the structure (`book.sections`, `linear !== 'no'`), never from `nextSection()` resolving to nothing, because it resolves `undefined` both when it moves and at the last section. A retry stops once the move is superseded.
- **`scrollToAnchor(range, false)`, and only when the sentence is off the page.** With `true` the paginator *selects* the sentence (`paginator.js:577-578`), which raises the Highlight chip and feeds the ask panel's selection on every sentence; scrolling on every sentence also wipes a selection the user is holding and restarts the position-save debounce through `relocate` (six on-page sentences emitted one relocate each before the guard, zero after). The plan's Fact 3 said `true`; this is the recorded deviation.
- **A speech fill never replaces a saved highlight.** The fill is drawn under the sentence's CFI as its `value`, so a user highlight on exactly that sentence would be replaced on the page, then wiped again by the next `replan`. The controller's required `isSaved(cfi)` dep (`isSavedValue` in `src/lib/annotations.ts`, the same rule as the plan's offer filter) skips the fill, and every deletion re-checks it so speech never deletes a highlight the user just saved. The speech kind is not in `ANNOTATION_DRAW_KINDS`, so it never enters the persisted plan. `isSaved` is slightly broader than the engine's rows: a highlight the engine refused to draw also counts as saved, and that one sentence gets no fill.
- **`show-annotation` for a speech fill must not open Notes.** `ReaderEngine`'s listener returns early unless `plan.current.rows` has the value's CFI; clicking the spoken sentence otherwise opens the Notes panel. Checked live: the click leaves `notesOpen` false and playback going.
- **The `AudioContext` is created inside `useSpeech` and closed on stop.** `player.stop()` closes it, so a closed bar is silent and holds no audio device; teardown runs on a book change, unmount, `listenOpen` going false (the close button, `L`, or the store closing the bar with the book) and any new session. A `generation` counter drops continuations still awaiting `status()` or `begin()` when the session changed. A suspended context is resumed before every restart (a Retry or a relocate restart on a paused-then-suspended context stalled until `resumeAndStart` existed). `ctx.state === 'running'` at the first `start()` is asserted live, not assumed.
- **Escape is a ladder with the listen bar on the last rung before the book, and `L` toggles the bar.** Search results, then the search, notes and prefs panels, then the bar (`closeListen()`), then the book, so a listener who presses Escape to quiet the voice does not lose their page; the ToC and Ask have no window Escape rung, so Escape with the ToC open closes the bar and then the book. Escape inside the voice `<select>` does nothing (`isTypingTarget`). The header Listen button and every bar button decline focus on mousedown so a later Space turns the page. Same-book reopen resets `listenOpen` like `tocOpen` and `prefsOpen`, which means double-clicking the open book closes the bar mid-playback.
- **Download state is hook-local, which bends the store-as-truth convention for this one slice (accepted).** Closing the reader mid-download and reopening shows "Download the voice (120 MB)" until it is pressed; the press rejoins the same job (main shares it), so nothing is fetched twice, but no progress shows in between. The reversal is to move the phase into the store.
- **The real model download, measured 2026-10-15.** 120,575,669 bytes in 3.70 s (32.6 MB/s, 98 progress events, one 302 from github.com to release-assets.githubusercontent.com, no rate limit); both sha256 and both sizes matched the pins. Cancel at 41.1 MB returned `{ status: 'cancelled' }` and left the directory empty (the `.part` removed); the bar returned to the needs-model line in 102 ms and a clean re-download took 4.73 s. The control lane held: `tts.status()` during a 63.5 s `reflow_pdf` of a 355-page book had a median of 0.5 ms and a max of 9.7 ms over 106 calls.
- **Background playback holds on the audio clock.** Minimized for 600 s (`isMinimized()` true, `visibilityState` hidden): 120 samples with a max inter-sample gap of 5.006 s, audio clock 595 s over 595 s of wall time (ratio 0.999 to 1.001), 92 buffers, longest silence between buffers 0.700 s (the block pause), none over 0.75 s, none scheduled late. Hidden with `app.hide()` for 180 s: ratio 0.999, same maximum silence. `backgroundThrottling` stays at its default. Not measured: heavy CPU contention (the one bulk-refresh run was network-bound, synthesis median 621 ms against 260 ms idle).
- **First-sentence latency: cold misses the 2 s target.** Press Play to first audible, fresh app: 1,796, 1,529 and 3,192 ms (median 1.80 s, worst 3.19 s; the worst run's first sentence was long). Warm: 656, 777 and 124 ms (median 0.66 s). Open item; the options are pre-warming the model or splitting a long first sentence (spec AC21).
- **The first sentence of a new section is synthesized inside the 700 ms pause.** Before `ended()` existed that synthesis overlapped the old last sentence. Measured spare on short chapter headings is 440 to 540 ms; a section that opens on a long sentence with a cold cache can overrun and lengthen the pause. Pre-synthesizing the next section's first sentence from `book.sections[i+1].createDocument()` would remove it; not built.
- **Known residuals.** A hand page turn inside the new section while the old section's last sentence is still sounding is read as our own move (one sentence wide). Read from here with a selection inside a block's last sentence still starts at the block's first sentence, because `from()` returns the whole block and the page filter would skip to the *next* block, which is wrong for a chosen place; the right answer is the sentence containing the selection. A single unit can be very long (87.6 s of audio in one Darwin section, inside the 4,000-character cap), so previous/next and the highlight are coarse there.
